    3Introducción

    3.1Propósito

    Este proyecto nació de una necesidad del INTI (Instituto Nacional de Tecnología Industrial): poder ver de forma simple, y con rigor técnico, las condiciones ambientales en las que su Laboratorio de Robótica (LABI) hace ensayos con robots.

    Para eso se coloca un datalogger autónomo dentro de la jaula donde está el robot, en un punto definido. El datalogger mide temperatura, humedad y presión, guarda cada medición en una tarjeta microSD y la envía por Wi-Fi, con el protocolo MQTT, a un servidor que está dentro del laboratorio. El servidor guarda los datos en una base de datos y los muestra en una página web alojada en el mismo servidor, en un dashboard con gráficas y valores numéricos fáciles de leer.

    3.6Resumen ejecutivo

    Objetivo. Construir un datalogger autónomo, alimentado por batería, que se comunique con el servidor del laboratorio para que cualquier integrante del equipo del LABI revise, desde una página web, el estado de lo que se está midiendo en ese momento.

    Público objetivo. El director y el equipo técnico del Laboratorio de Robótica del INTI.

    Resultados esperados. Un datalogger funcionando dentro de la jaula del robot, un servidor propio con broker, base de datos y web publicados, y un testing de al menos una semana con el cliente, antes de las presentaciones finales de noviembre y de la Expo.

    4Descripción general

    4.1Perspectiva del producto

    El producto es una parte de un sistema mayor. Hoy el LABI tendrá un solo datalogger, pero con el tiempo podría sumar equipos nuevos, que se conectarían al mismo servidor y se monitorearían de forma remota desde la misma web.

    Prototipo y versión final

    El repositorio de GitHub contiene hoy el prototipo del datalogger: el ESP32 guarda las mediciones en la microSD y sirve una web local. El producto final usa el servidor del INTI: el datalogger envía las mediciones por MQTT al broker, se guardan en MariaDB y la web se aloja en ese servidor. La web del prototipo es la base del dashboard final.

    4.2Funcionalidad del producto

    La función principal es que el equipo del LABI monitoree de forma remota las mediciones del datalogger durante las pruebas y ensayos que hace con sus robots y su material. Además:

    • mide temperatura, humedad y presión, con fecha y hora;
    • muestra los valores en la pantalla del propio equipo y los guarda en una microSD;
    • envía las mediciones al servidor y las muestra en gráficas y valores numéricos;
    • marca como alerta las mediciones fuera de rango;
    • permite descargar los datos para analizarlos después.

    4.3Características de los usuarios

    Tipo de usuario
    Director del Laboratorio de Robótica del INTI.
    Formación
    Técnico en electrónica, técnico superior en automatización y robótica, profesor en disciplinas industriales especializado en automatización y robótica, especialista en calidad industrial.
    Actividades
    Realiza pruebas y ensayos con los robots del laboratorio, crea y dirige prácticas universitarias, arma rúbricas y guías de robótica.

    4.4Restricciones

    4.4.1 Políticas reguladoras

    La web del producto es software libre para uso del equipo del laboratorio. Las herramientas que sostienen el sistema (Mosquitto, MariaDB y el núcleo de Arduino para ESP32) son libres y no requieren licencias pagas. El código queda en un repositorio de GitHub. Los datos medidos pertenecen al INTI y permanecen en su servidor. El sistema no guarda datos personales, salvo el usuario y la contraseña de acceso.

    4.4.2 Limitaciones de hardware

    Los requisitos mínimos son: un datalogger con microcontrolador (ESP32), una batería (Li-ion de 850 mAh), sensores que midan temperatura, humedad y presión, una red inalámbrica que comunique el datalogger con el servidor, y una base de datos (MariaDB) en el servidor. El detalle está en 5.3.

    4.4.3 Interfaces con otras aplicaciones

    No hay por el momento. El sistema funciona de forma independiente dentro del laboratorio.

    4.4.4 Función de control

    La web tiene un solo tipo de autenticación: ingresar con un usuario y una contraseña entregados por el director del LABI.

    4.4.5 Requisitos del lenguaje

    El lenguaje para entender la web es natural y técnico. La parte natural: la interfaz está en español (el idioma no se cambia desde la configuración) y las fechas se muestran con el calendario gregoriano. La parte técnica: las unidades de las mediciones, y el código de color en formato RGB que se usa para cambiar el color de las funciones de los gráficos. Aunque la pantalla para cambiarlos es intuitiva, expresar el color en RGB es lenguaje técnico.

    4.4.6 Protocolos señalados

    • Red: MQTT, porque usa pocos recursos y poca densidad de datos; e IP, por la dirección del servidor donde se aloja la web.
    • Web: HTTPS, que agrega una capa de cifrado.
    • Diagnóstico: ICMP, para informar errores de conexión del datalogger con la web.
    A completar por el equipo

    El informe anterior decía "a chequear con Puleo y Feli si se puede realizar y si se realizó". Si no se implementó, hay que sacar ICMP de la lista o pasarlo a la evolución futura (4.6).

    4.4.7 Requisitos de fiabilidad

    Se establecen con el testing con el cliente: 7 días de funcionamiento continuo, sin pérdida de datos y con una latencia menor a 2 segundos (ver 9.6). Los resultados se anotan en la bitácora (10.4).

    A completar por el equipo

    Cuando termine el testing de 7 días, anotar acá los resultados reales: horas de funcionamiento, mediciones perdidas y duración de la batería.

    4.4.8 Credibilidad de la aplicación

    Se verifica con una entrevista al usuario para comprobar que los valores que muestra la web coinciden con lo que él espera de su laboratorio, y con una comparación contra un instrumento de referencia del LABI.

    A completar por el equipo

    La entrevista de credibilidad figura en la Gantt (tarea 5.1) y todavía no se hizo. Cuando se haga, anotar fecha y conclusiones en 10.1.

    4.4.9 Consideraciones de seguridad

    • El acceso a la web requiere usuario y contraseña.
    • La web usa HTTPS, así que lo que viaja entre el navegador y el servidor va cifrado.
    • El broker MQTT y la base de datos están dentro de la red del laboratorio y se configuran con credenciales propias.
    • La base de datos usa restricciones de clave foránea: no se puede borrar un dispositivo que tiene mediciones.
    • La batería nunca se conecta directo al pin de 3,3 V del ESP32 (el máximo es 3,6 V y una celda cargada llega a 4,2 V): entra por el pin de 5 V a través del módulo de carga.

    4.5Suposiciones y dependencias

    El proyecto se hace para un organismo estatal y depende de factores que están fuera del control del equipo:

    • Continuidad del área. Si el INTI reorganiza o cierra el área de robótica, el LABI dejaría de existir y el proyecto perdería a su usuario.
    • Presupuesto. Si el INTI atraviesa una etapa de bajo presupuesto, podría no costear el proyecto como corresponde.
    • Servidor y red. Se supone que el INTI mantiene encendido el servidor y que la red Wi-Fi del laboratorio funciona en la banda de 2,4 GHz, que es la que usa el ESP32.
    • Acceso al cliente. Se supone que el director del LABI puede reunirse con el equipo en las fechas del testing.
    • Tiempos escolares. El trabajo se hace dentro del calendario del Instituto Leonardo Murialdo, con entrega a principios de noviembre.

    5.6Modelo entidad-relación

    La base de datos datalogger1 está en MariaDB. Tiene tres tablas, tres vistas y tres funciones. Se diseñó para que cada dato se guarde una sola vez y para que sumar un datalogger nuevo sea agregar una fila.

    Normalización

    Forma normalQué exigeQué se encontróCómo se resolvió
    1FNUn valor por celda, sin grupos repetidos.Cada medición trae varias variables.Una fila por medición, con una columna por variable (temperatura, humedad, presión).
    2FNCada dato depende de toda la clave.Todas las tablas tienen clave simple (id).Se cumple sin cambios.
    3FNNingún dato depende de otro dato que no sea la clave.El nombre de la ubicación se repetiría en cada dispositivo y en cada medición.Se separó en la tabla ubicacion; el nombre del dispositivo vive en dispositivo.
    Una decisión consciente

    La columna estado (NORMAL o ALERTA) se puede calcular a partir de temperatura, humedad y presión. Se guarda igual a propósito: así las alertas se consultan rápido y la regla queda escrita en una función (fn_clasificar_estado).

    • Dimensiones: dispositivo (qué equipo midió), ubicacion (dónde estaba) y el tiempo (fecha_hora).

    -- Tablas (extracto simplificado)
CREATE TABLE `ubicacion` (
  `id` int(11) NOT NULL AUTO_INCREMENT,
  `nombre` varchar(50) NOT NULL,
  PRIMARY KEY (`id`)
);

CREATE TABLE `dispositivo` (
  `id` int(11) NOT NULL AUTO_INCREMENT,
  `nombre` varchar(50) NOT NULL,
  `id_ubicacion` int(11) NOT NULL,
  PRIMARY KEY (`id`),
  FOREIGN KEY (`id_ubicacion`) REFERENCES `ubicacion` (`id`)
);

CREATE TABLE `medicion` (
  `id` int(11) NOT NULL AUTO_INCREMENT,
  `id_dispositivo` int(11) NOT NULL,
  `fecha_hora` datetime NOT NULL,
  `temperatura` decimal(4,1) NOT NULL,
  `humedad` decimal(4,1) NOT NULL,
  `presion` decimal(5,1) NOT NULL,
  `estado` enum('NORMAL','ALERTA') NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_fecha_hora` (`fecha_hora`),
  FOREIGN KEY (`id_dispositivo`) REFERENCES `dispositivo` (`id`)
);

-- Regla de alertas
CREATE FUNCTION `fn_clasificar_estado`(
  p_temperatura DECIMAL(4,1), p_humedad DECIMAL(4,1), p_presion DECIMAL(5,1)
) RETURNS VARCHAR(10) NO SQL DETERMINISTIC
BEGIN
  IF p_temperatura >= 35 OR p_humedad >= 80
     OR p_presion < 990 OR p_presion > 1020 THEN
    RETURN 'ALERTA';
  END IF;
  RETURN 'NORMAL';
END;

-- Vista usada por la pantalla de alertas
CREATE VIEW `view_alertas` AS
SELECT m.id, d.nombre AS dispositivo, u.nombre AS ubicacion,
       m.fecha_hora, m.temperatura, m.humedad, m.presion
FROM medicion m
JOIN dispositivo d ON m.id_dispositivo = d.id
JOIN ubicacion u ON d.id_ubicacion = u.id
WHERE m.estado = 'ALERTA';
    Consecuencias prácticas
    • Sumar un datalogger nuevo es insertar una fila en dispositivo.
    • Mover un datalogger de lugar es cambiar un solo dato (id_ubicacion); las mediciones viejas siguen asociadas al equipo.
    • La clave foránea impide borrar un dispositivo que tiene mediciones, así que no quedan datos huérfanos.
    • El índice idx_fecha_hora acelera las consultas por rango de fechas del dashboard.

    5.7Diagrama de flujo

    El diagrama sigue una medición desde que el datalogger la toma hasta que el usuario la ve. Cada carril es un responsable: el datalogger, el servidor del INTI y la web con su usuario.

    1. Al encenderse, el datalogger lee el sensor y el reloj en cada ciclo de muestreo.
    2. Muestra el valor en su pantalla y lo guarda siempre en la microSD, haya o no red.
    3. Si hay Wi-Fi y broker, publica la medición por MQTT. Si no, espera al próximo ciclo: no pierde el registro porque ya quedó en la microSD.
    4. El broker del servidor recibe el mensaje y un servicio lo guarda en la tabla medicion.
    5. La función fn_clasificar_estado marca la medición como NORMAL o ALERTA.
    6. La web consulta las vistas y muestra el dashboard. Si el estado es ALERTA, la resalta.

    11Guía de inicio rápido

    Para usar el datalogger por primera vez, en una página. Si algo no funciona, mirá las preguntas frecuentes (sección 12).

    Antes de empezar
    • El datalogger con la batería cargada y una tarjeta microSD.
    • La red Wi-Fi del laboratorio disponible (banda de 2,4 GHz).
    • El servidor del INTI encendido.
    • Un usuario y una contraseña para la web, que entrega el director del LABI.

    1. Cargá el datalogger Usuario del LABI

      Conectá el cable USB al módulo de carga hasta que la batería esté llena. Hacelo antes del ensayo.

    2. Insertá la microSD y encendelo Usuario del LABI

      Con la tarjeta puesta, encendé el equipo. La pantalla muestra la fecha, la hora y las mediciones de temperatura, humedad y presión.

      Captura de la pantalla del dataloggerFoto del equipo encendido.

    3. Ubicalo en la jaula Usuario del LABI

      Colocá el datalogger en el punto definido dentro de la jaula del robot y fijalo para que no se mueva.

    4. Iniciá el registro Usuario del LABI

      Presioná el pulsador una vez para empezar a registrar. Con la misma tecla, más adelante, lo detenés.

    5. Entrá a la web Director o equipo

      Abrí la dirección de la web del laboratorio e ingresá con tu usuario y contraseña. Vas a ver el dashboard.

      Captura del inicio de sesiónPantalla de ingreso.

    6. Mirá las mediciones y las alertas Director o equipo

      En el dashboard se ven las gráficas y los valores. En Alertas aparecen las mediciones fuera de rango. Si necesitás los datos, usá la exportación.

      Captura del dashboardGráficas y valores.

    7. Terminá el ensayo Usuario del LABI

      Presioná el pulsador para detener el registro y apagá el equipo. Los datos quedan en la microSD y en la base de datos.

    12Preguntas frecuentes

    ¿Qué mide el datalogger?
    Temperatura, humedad y presión, con fecha y hora (RF-01), con un sensor BME280.
    ¿Qué pasa si se corta el Wi-Fi o el servidor?
    El datalogger sigue guardando cada medición en la microSD, así que el registro no se pierde (RF-03 y RNF-05). Cómo se cargan después esos datos a la base se define en el testing.
    ¿Cuánto dura la batería?
    Es una batería Li-ion de 850 mAh. La duración real se mide en el testing con el cliente (RF-08 y RNF-03).
    ¿Qué significa ALERTA?
    Que una medición está fuera de rango: temperatura de 35 °C o más, humedad de 80 % o más, o presión menor a 990 hPa o mayor a 1020 hPa. La regla está en la función fn_clasificar_estado (5.6).
    ¿Puedo cambiar los umbrales o la frecuencia de medición?
    Sí, desde la pantalla de configuración (RF-05).
    ¿Quién me da el usuario y la contraseña?
    El director del LABI (4.4.4).
    ¿Puedo ver la web desde el celular?
    Sí, la interfaz se adapta al tamaño de la pantalla (RNF-07), siempre dentro de la red del laboratorio (L-06).
    ¿Puedo cambiar el idioma?
    No. La interfaz está solo en español (L-02).
    ¿Se pueden sumar más dataloggers?
    La base de datos ya está preparada: cada datalogger nuevo es una fila en la tabla dispositivo (5.6). En esta entrega funciona uno (L-04) y se amplía en la versión 2.
    ¿Recibo notificaciones en el celular?
    No en esta versión (L-01). Está prevista para la versión 1.1 (4.6).
    ¿Puedo bajar los datos para usarlos en Excel?
    Sí. La web permite exportar los datos (RF-07) y los archivos CSV se abren con cualquier planilla.
